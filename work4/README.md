# Работа 4: CUDA WMMA / Tensor Cores

Подготовлено для запуска на RTX 2060 (compute capability 7.5), Windows, CUDA 13,
MSVC 14.39, CMake >=3.24, Ninja. Сборка и выполнение CUDA на компьютере автора
подготовки не проверены: здесь нет GPU/CUDA. Настоящие результаты появятся только
после запуска на целевой машине. Предыдущие работы не изменены.

## Запуск на нашем втором ПК

В **cmd**, по одной строке (предполагается прежний каталог H:\hsys):

```bat
cd /d H:\hsys
git pull --ff-only
cd work4
build.cmd
```

`build.cmd` использует уже открытое окружение MSVC либо прежний путь
`H:\BuildTools2022\VC\Auxiliary\Build\vcvarsall.bat` и toolset 14.39.
Если путь изменился, сначала открыть x64 Developer Command Prompt VS 2022.
Скрипт останавливается при ошибке; не запускать измерения после неудачной сборки.
Первое конфигурирование скачивает Eigen 3.4.0, Google Test 1.15.2 и
Google Benchmark 1.9.1. Архитектура в build.cmd явно 75.

Закрыть игры и тяжёлые приложения. В том же окне:

```bat
run.cmd
```

Нужен установленный Python 3.9+; для тестов и замеров Python-пакеты не нужны.
Сначала выполняются **225 тестов** (216 комбинаций + 9 дополнительных).
Только после успеха запускаются 3 метода x 7 размеров x 5 повторов.
Создаётся новая папка `results/YYYYMMDD-HHMMSS`, а также ZIP рядом с ней.
Если запуск завершился ошибкой, ZIP сохраняет диагностику, но не считается
успешным экспериментом. `results/latest.txt` обновляется только при успехе.

Сохраняются XML тестов, полный JSON замеров, вывод программ, модель CPU/GPU,
ОС, версии CUDA, хеш Git и состояние исходников. Скрипт не обновляет драйверы,
не меняет глобальную PowerShell policy; Bypass относится к одному процессу.

## Графики и черновик отчёта

Совместимо с имеющимся Python 3.9.4. После успешного `run.cmd`:

```bat
python -m pip install -r scripts\requirements.txt
```

Подставить папку запуска из `results/latest.txt` вместо `YYYYMMDD-HHMMSS`:

```bat
python scripts\plot.py results\YYYYMMDD-HHMMSS
python scripts\make_report.py --results results\YYYYMMDD-HHMMSS --output results\YYYYMMDD-HHMMSS\report.docx
```

Графики PNG, таблица CSV и summary создаются только после проверки всех 225 тестов,
наличия всех 105 измерений и метаданных. Используется медиана; полоса - min/max,
не доверительный интервал. Генератор отчёта сверяет хеши исходных файлов и графиков.
Python-генератор отчёта сохранён в ASCII с Unicode escapes: кириллица в DOCX
сохраняется, проблема кодировки из работы 3 не повторяется.

Отчёт содержит методику, ключевой WMMA-код, оборудование, реальные таблицы,
графики и вычисленные выводы. Его нужно визуально проверить, уточнить титульник
и оформление по СТУ перед сдачей. Без результатов окончательного отчёта нет.
Запуск plot.py/report после run.cmd не обновляет уже созданный ZIP; при необходимости
упаковать папку результатов заново.

## Реализация и ограничения

- `Data<T>`: RAII GPU-память, deep copy, move. Допускает `__half`, который не является
  `std::is_arithmetic`. `Matrix<T>` копируется с совместным владением.
- `MatrixView<T>`: row-major, невладеющее тривиально копируемое представление.
- `kernel_matmul_wmma` получает три MatrixView по значению. Блок 256 потоков = 8
  полных варпов. Каждый варп вычисляет 16x16; расположение варпов 2x4 даёт блок 32x64,
  как схема задания. Shared tiles A:32x16, B:16x64, всего 3072 байта.
- `load_matrix_sync`, `mma_sync`, `store_matrix_sync`: вызываются всеми 32 lanes
  варпа с одинаковыми параметрами. Shared-массивы выровнены на 32 байта; шаги 16/64
  half-элементов. Выход cudaMalloc выровнен; шаг строки кратен 16 float-элементам.
- FP16 входы, FP32 аккумулятор и выход. `Matrix<__half> * Matrix<__half>` возвращает
  `Matrix<float>`. Конвертация входов выполняется до измеряемого интервала.
- Размеры WMMA должны быть кратны 16 (включая ноль). Неподдерживаемые размеры
  отклоняются исключением; тихого отката на другой алгоритм нет.
  Неполные блоки 32x64 дополняются нулями при загрузке; разрешённые выходные плитки
  16x16 всегда целые. Барьеры достигаются всеми потоками блока.
- Нулевой внутренний размер даёт нулевую матрицу; пустой выход не запускает кернел.
- Это учебная реализация, не cuBLAS и не обещание максимального ускорения.

## Корректность и точность

216 тестов покрывают все m,k,n из {16,32,64,128,256,512}.
Эталон: реальное произведение двух
`Eigen::Matrix<Eigen::half,Dynamic,Dynamic,RowMajor>`, затем cast в MatrixXf.
Проверяются `MatrixXf::isApprox(...,1e-2f)` **и** абсолютная ошибка <=1e-2,
так как isApprox - относительная проверка, несмотря на формулировку задания.
Дополнительно сравниваем с Eigen FP32 и обоими shared-memory вариантами.

Основные входы {-1/16,0,1/16}: произведения и промежуточные суммы при k<=512
точно представимы в half. Отдельный тест использует обычные случайные дробные
числа из [-0.01,0.01], округлённые в half. Абсолютная ошибка 0.01 для произвольных
по масштабу входов не обещается. Нельзя ослаблять тесты ради прохождения.
Дополнительные тесты проверяют границы блока, ошибки размеров, ownership и overflow.

## Честное сравнение

- `BM_WMMA`: новый operator* для Matrix<__half>, результат FP32.
- `BM_SharedFP32`: предыдущий operator* для Matrix<float>, shared-memory алгоритм
  работы 3 (16x16, по элементу на поток). Это основной знаменатель сравнения.
- `BM_SharedFP16`: дополнительный контроль, FP16 входы с FP32 арифметикой на обычных
  CUDA cores; преобразования half->float входят в kernel time.

Численные входы всех методов одинаковы: q/16, q из [-8,8]. Формат хранения
предыдущего варианта FP32, нового FP16: основной speedup сравнивает реализации,
а не изолирует только влияние Tensor Cores. Дополнительный контроль помогает
увидеть влияние формата, но тоже не заменяет аппаратное профилирование.

CUDA Events стоят вокруг реального запуска в пути operator*: cudaMalloc результата,
копирование, конвертация и cudaFree вне интервала. 3 прогрева, 5 повторов по минимум
0.2 с. Время измеряется в том же default stream. Все графики - compute-only,
не полное время приложения. Основное ускорение = median(SharedFP32)/median(WMMA).
Результаты работы 3 не переиспользуются: оба метода измеряются заново на одном ПК.

## Диагностика памяти (по желанию)

Если установлен Compute Sanitizer, в Developer Command Prompt:

```bat
compute-sanitizer --tool memcheck --leak-check full build\bin\matrix_tests.exe
compute-sanitizer --tool synccheck build\bin\matrix_tests.exe --gtest_filter=WmmaEdges.*
```

Не запускать sanitizer во время измерения производительности.

## Публикация результатов

После проверки протоколов и отчёта добавить **конкретную папку** запуска:

```bat
git add -f results/YYYYMMDD-HHMMSS
git diff --cached --stat
git commit -m "Add work4 RTX 2060 experiment"
git push origin main
```

Не добавлять build/ и .venv/. Нельзя заявлять успешный запуск до проверки XML/JSON.
